# 榫卯结构拆解图鉴

面向传统木作学习者与家具设计人员的纯前端单页应用。项目把榫卯类型、构件尺寸、配合公差、拆装步骤、内联 SVG 示意图与适用家具整理为一套可查询、可编排、可追溯的本地图鉴，所有数据均保存在当前浏览器中。

## Docker 一键启动

```bash
cp .env.example .env && docker compose up -d --build
```

服务启动后访问：`http://localhost:21804`

停止服务：

```bash
docker compose down
```

## 数据存储说明

应用使用 IndexedDB，数据库封装库为 Dexie 4，库名为 `gbmortise-db`。

- `version(1)`：建立 `joints`、`members`、`steps`、`diagrams`、`furniture` 五张表及查询索引。
- `version(2)`：执行升级迁移，为五张表回填 `schemaRev = 2` 字段。
- `version(3)`：装配计划升级。`steps` 表新增 `memberIds`（关联构件）与 `prerequisiteIds`（前置步骤）；新增 `stepExceptions`（老师例外）表及索引；旧步骤统一回填空关联——缺构件、非首步缺前置会在校验中进入「待补关系」。
- 首次创建数据库时通过 Dexie `populate` 回调写入榫卯、构件、步骤（已带构件与前置关联）、内联 SVG 与家具关联的种子数据。
- 新建记录、尺寸修改、SVG 保存、步骤拖拽调序与步骤关联编辑都会实时写回 IndexedDB，刷新页面后仍可读取。

## 装配计划与校验规则

步序、类型详情与导出共享同一份装配计划。每个步骤都关联构件和前置，并带施力方向与使用工具；每次拖动调序或编辑保存都会对整份计划重新校验。

| 类别 | 校验码 | 判定 |
| --- | --- | --- |
| 硬性阻挡 | 前置成环 | 前置关系出现环路（含自环，Tarjan 强连通分量判定），环上步骤无法标为可执行 |
| 硬性阻挡 | 方向互锁 | 相邻步骤作用于同一构件且施力方向为轴向/侧向/斜向中的相异两向 |
| 硬性阻挡 | 工具冲突 | 相邻两步使用同一件手持工具（木槌/鱼线/撬板），同抢工具 |
| 待补关系 | 缺关联构件 | 步骤未关联构件，或关联构件已被删除（不阻挡执行） |
| 待补关系 | 缺前置步骤 | 非首步未登记前置，或登记的前置已不存在（不阻挡执行） |

- 存在未放行硬性阻挡的步骤**不能标为可执行**，步骤轨道与导出 JSON 都会写清具体阻挡原因和涉及步号。
- 调序或编辑引入新阻挡时**整体事务回滚**：步骤顺序、步骤内容与老师例外状态都回到改动前，页面显示回滚横幅和阻挡原因。
- **老师例外**只能针对三类硬性阻挡逐条放行，需写明依据。例外保存授权时的关联内容指纹（动作、方向、工具、关联构件、前置；不含步号、风险提示、停留秒数）；关联内容一旦修改，指纹不符的旧例外自动失效并从库中清除，需重新核实。单纯拖拽改步号不改变指纹。

## 核心功能与路由表

| 路由 | 页面 | 核心功能 |
| --- | --- | --- |
| `/` | 入口重定向 | 自动进入榫卯图鉴 |
| `/joints` | 榫卯图鉴总览 | 按家族与难度分组，新建类型，显示构件数与步骤数，导出全部数据 |
| `/joints/:id` | 类型详情 | 查看尺寸表、公差校验、适用家具与装配计划步序（含阻挡原因）；导出当前类型与装配计划 |
| `/joints/:id/steps` | 装配计划编排 | 步骤关联构件与前置、设置方向与工具，拖拽/编辑事务化校验，老师例外登记，逐步预览 SVG，导出装配计划 |
| `/joints/:id/diagram` | 示意图绘制台 | 点击热区回填构件，编辑构件名称、尺寸与 SVG 源 |
| `/furniture` | 家具榫卯反查 | 按家具聚合使用部位与承力说明，新建家具关联 |
